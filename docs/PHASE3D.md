# Phase 3D v0.8.0：4産業投資・非公開上限・資源特性

## 実装範囲

primary（第1次）、secondary（第2次）、tertiary（第3次）、quaternary（第4次）の4産業へ、現在係留している惑星で投資できます。進捗は惑星・クール単位で共有し、資金は投資者からだけ減算します。投資額と効果量は別記録です。別BBSの同名・同IDアカウントを統合しません。
工作船は設定された効果ボーナスを受けます。資源特性は惑星に保持し、未開拓（進捗0）でも希少資源の定義を保持します。鉱物発見の抽選・報酬はPhase 3G、航路投資は3F、船の販売解禁は3Eです。今回それらの動作を先取りしません。

## 有効化と互換性

既存の設定未指定/nullはdevelopment.mode=disabledとなり、既存DBに投資条件・上限・資源を勝手に割り当てません。旧世界のdevelopmentコマンドは未設定を表示し、投資は拒否します。
examples/phase3d-trial.jsonで新しい試遊世界を作成してください。既存DBは保存済みカタログを使用し、ファイル差し替えで設定を変更しません。正式値確定後の既存世界への設定移行は別途設計します。

## 試遊設定（共有Game Rules）

developmentに以下を定義します。

- mode: disabled、またはlinear_units_v1。
- status: 有効な試遊方式ではprovisionalのみ。正式仕様ではありません。
- credits_per_unit: 4産業それぞれの効果1単位当たりのCr。正の整数。
- engineering_bonus_bps: 工作船の効果加算率。試遊方式の受入範囲1〜10,000 bps。
- planets: 全惑星を重複なく列挙。
- planet_id: 既存惑星ID。
- initial_progress: 4産業それぞれの初期進捗。
- private_caps: 4産業それぞれの非公開上限。初期進捗以上。
- resources: resource_id（安定ID）、abundance（0〜10,000の資源特性値）、rare（希少資源フラグ）。IDは惑星内で重複不可。

試遊方式は産業別に独立した上限を使います。これを正式方式に決定したわけではなく、全産業合計上限や成長曲線などへの変更は別modeとして追加可能です。
試遊例の換算率は10/20/25/50 Cr、工作船ボーナス2,500 bps、初期進捗0。惑星ごとに異なる上限と資源を設定しています。数値はサーバー側の試遊JSONで管理します。

## 試遊計算

投資額をA、産業の換算率をRとすると、AはRの正の整数倍を要求し、基本効果=A/R。
通常船・仮装巡洋艦は基本効果、工作船は基本効果+floor(基本効果×bonus_bps/10000)。現金減算はどの船もAのまま。丸めは取引単位の切捨てです。
例: 第1次産業へ400 Cr投資すると、通常船40単位、工作船50単位（試遊率）。100 Crの場合は通常船10、工作船12単位。

上限を超える投資は全額拒否し、資金・進捗・履歴を変更しません。残り枠だけの部分受理はしません。上限ぴったりは受理します。満額到達の特別通知はしません。係留中のみ実行可能で、リモート惑星指定や航行中投資はありません。
需要供給の時間更新は既存のゲーム操作と同じトランザクションに含まれます。失敗時は時間更新も巻き戻します。産業投資が市場生産/価格へ与える直接効果は未実装・未確定です。

## 非公開情報の境界

private_capsはサーバー側カタログ/DBだけで保持し、共有ルールのハッシュには含めます。Applicationの公開応答・成功結果・失敗メッセージ・履歴・CLIには上限、残り枠、達成率、上限到達フラグを出しません。開発進捗そのものは表示します。上限超過は値を伴わない一般的な受付不可エラーです。
資源の公開応答はresource_idのみ。abundanceとrareは内部保持し、公開DTOへ丸ごとコピーしません。日英表示名は言語ファイルのnames.resourcesで管理します。
この設計は上限値の直接漏出を防ぐものです。公開進捗と投資の成否から可能な推測まで不可能にする保証ではありません。推測抑止が必要な場合の試行制御や公開進捗の粒度は確認事項です。

Catalog.effective_rules()は内部管理専用で、上限を含みます。これをWeb等へ返してはいけません。config-infoは従来の信頼されたローカル管理用CLIで、世界ID・版・ハッシュのみを返します。正規設定の配布/認証境界はPhase 5の設計対象です。サーバーファイルを読める管理者に対して上限を秘匿するものではありません。

## 保存と履歴

DBスキーマ7。planet_developmentとinvestment_recordsを追加。旧1〜6から移行前バックアップを作り、同一トランザクションで移行します。旧世界の資産・市場・航路・船・世界ID・取引台帳・航行・再送履歴を維持します。
投資履歴にはpaid_creditsとeffect_units、進捗前後、主体/惑星/産業/クール、時刻、request_id、内部ルール版/ハッシュを記録。公開履歴は許可項目だけを選び、内部設定を含めません。
操作履歴・資金・進捗・投資履歴を同時に確定します。同じrequest_idの再送は元結果を返し、二重に支払/成長しません。同じrequest_idの内容変更は拒否。最後の枠への競合も直列化し、成功する投資だけを記録します。
履歴はプレイヤー別、既定50件/最大100件でsequenceカーソルを使います。過去データから投資を推定生成しません。異常な保存進捗は黙って補正せず検証エラーにします。

## ハッシュと未確定事項

rules_version=phase3d-1、設定射影スキーマ3、DBスキーマ7。developmentの有効設定（上限・資源特性を含む）をハッシュへ追加。惑星と資源の並び順を正規化し、status・言語表示名・変動する開発進捗は除外します。ルール版更新で以前の版からハッシュは変わります。既存見積りcanonicalや保存済み要求結果は維持。

確認事項:
1. 正式な投資効率・成長曲線、上限が産業別か全体か、部分受理の要否。
2. 工作船ボーナス率、丸めと投資分割の扱い、許容する率の範囲。
3. 公開する開発進捗の粒度、上限推測への対処要否。
4. 資源分類・abundanceの意味/尺度と公開範囲、第1次産業と採掘/生産への接続。
5. 希少鉱物発見の確率/条件/報酬（3G）。未開拓でも可能性を残す確定方針は維持。
6. 船購入の産業条件（3E）、航路投資との評価（3F）、貢献ランキングの支払額/効果量評価（4）。

Inter-BBS通信・接続判定はPhase 5のまま。外部言語パックを使用している場合は新しい表示キー/エラーキーを同梱言語ファイルから追加してください。
