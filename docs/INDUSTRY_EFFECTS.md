# ECON-05：産業開発による生産能力・市場容量への効果

v0.12.0 / 2026-11-01。ECON-01〜04とPhase 3Dを維持した追加実装。
Inter-BBS通信・接続判定はPhase 5のまま。

## 実装範囲

新規世界で `examples/industry-effects-trial.json` を選択すると有効になります。
既存設定で `industry_effects` がない場合、または `{"mode":"disabled"}` の場合は従来通り。
旧DBの保存済みカタログは変更しません。既存世界へ異なる設定を指定すると従来通り拒否します。

産出定義の `industry` に対応する開発進捗が、その商品の国内生産に作用します。
試遊例は第1次=穀物/核融合燃料、第2次=合金、第4次=医薬品/高密度ワープ燃料。
第3次の進捗は全商品の市場在庫容量に作用します。
各惑星の産出品・基礎生産量・産業対応は維持し、非産出品は生産ゼロのままです。
輸入量・需要消費量・価格曲線の目標在庫・地域基準価格は直接変更しません。
生産増加による実際の在庫変化が既存の数量別価格へ反映されます。急騰/急落は引き続き独立して加算されます。
燃料商品と航行費用の分離、通常航行/係留0 Crも維持します。

## 暫定式と共有ルール

モード `next_period_v1`、`status: provisional`。
全惑星に `production_bps_per_unit`（4産業それぞれ）と `market_bps_per_unit` を指定します。
係数は0〜10000の整数。0で個別効果を無効化できます。浮動小数・真偽値・未知キー・欠落・重複を拒否します。

```
国内生産量 = 基礎生産量 + floor(基礎生産量 × 対応産業の進捗 × 生産係数 / 10000)
市場容量 = 基礎在庫上限 + floor(基礎在庫上限 × 第3次産業の進捗 × 市場係数 / 10000)
期間内の純供給 = 国内生産量 + 既存輸入量 - 既存需要消費量
```

試遊値は通常の生産係数100、市場係数50。Forgeの第1次生産係数は50として惑星差を例示。
Auroraの穀物は進捗0で6、進捗100で12。Forgeは同じ進捗100でも2から3です。
第3次進捗20なら市場容量10,000から11,000。小さい生産量では整数切捨てで効果がまだ表れない場合があります。
惑星固有の非公開開発上限を従来の投資処理で維持するため、投資を無制限に積み上げることはできません。
最大到達時の量を設定読み込み時に検証し、内部整数限界を超える設定を拒否します。

これらの設定・産出定義・非公開上限はサーバー専用の共有ルールに含めます。
ルール版 `phase3-industry-effects-1`、設定スキーマ7、正規化方式 `srt-integer-json-v1`。
係数変更はSHA-256へ反映され、惑星定義の順序変更は同じハッシュになります。
開発進捗・市場在庫・価格・期間別能力は動的状態であり、設定ハッシュには含めません。
表示言語・Inter-BBS接続先等のサイト設定も引き続き対象外です。
投影形式と版が変わるため旧版とはハッシュ値が変わりますが、既存の取引履歴に記録済みのハッシュは書き換えません。

## 反映時点と保存

生産周期は既存の `economy.tick_seconds` と `economy_clock` を使います。
各期間の開始時に、その期間に使う国内生産能力と市場容量を固定します。
投資時はまず完了済み期間を精算し、その後に進捗を更新します。
進行中の期間には投資効果を遡及せず、次の境界で新しい能力・容量へ切り替えます。
切替時に商品を無料配布したり、在庫を新しい容量まで補充したりしません。
新能力による生産は切替後の期間が完了した時点から入荷します。
境界と同時刻の投資も、精算後に実施されるため次の境界で切り替えます。

例：開始100、周期60、時刻159で生産進捗100へ投資。
時刻160では旧能力6から需要1を引いた5が入荷し、能力を12へ切替。
時刻220では12から需要1を引いた11が入荷します。再起動しても同じです。
大量の時間経過も「保存した能力で最初の1期間、現在の進捗で残りの期間」を一括計算し、定期更新と一致させます。
初期進捗を設定した新規世界では最初からその進捗による能力を使用します。

DBスキーマ9へ追加する `industry_periods` は世界/クール内の惑星・商品別に生産量と容量を保持します。
既存テーブル・データは維持。旧DBは移行前バックアップを作り、移行はトランザクション内で実施します。
旧設定で効果が無効なら新テーブルは空です。欠落・範囲外の保存値は検証エラーにします。
投資・入出荷・能力切替・所持金・台帳は同じSQLiteトランザクションで保存し、失敗時は全て戻します。
同一リクエストの投資再送は二重計上せず、ローカルの並行アクセスでも供給は二重加算しません。
復旧時は旧版と移行前バックアップを組にして使用してください。

## 表示と互換性

`production` は現在の期間に適用中の能力と在庫を表示します。
有効世界だけ追加で「現期間の市場容量」を表示します。これは売却を受け入れる現在の在庫容量です。
惑星の開発上限・上限までの残量・上限に対する達成率・資源の埋蔵特性は公開しません。
無効世界では既存のAPI返却項目と表示を維持します。
独自言語ファイルには `production_capacity` を追加してください。標準日英ファイルと表示スキーマに例があります。

```
python -m starroute --db data/industry-trial.db --config examples/industry-effects-trial.json --player captain
register Captain
production
invest primary 1000
invest tertiary 500
production
config-info
```

時間・保存・再送を含む日英CLI試遊：`python scripts/industry_effects_demo.py`。
自動試験：`python -m unittest discover -s tests -v`。
