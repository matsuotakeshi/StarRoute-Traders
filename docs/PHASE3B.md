# Phase 3B — 通常航行・ワープ・燃料費・係留 (v0.4.0)

2026-11-01。燃料費や移動時間の正式な計算式は選定しない。
明示的な設定表を読み、見積りと確定を同じルールで処理する基盤を実装。

## 今回の仕様

- 新規の通常航行は全船・全航路で追加料金0 Cr。routes/quote/go/departで一致する。
- 既存route.feeは履歴互換のため保存するが、新規通常航行に課金しない。
- 係留は全惑星・全船・全グレードで0 Cr。時間課金なし。反復操作による資産付与もなし。
- 航行中は係留・売買・別の出発不可。到着済みなら遅延更新で自動的に到着処理して操作可能。
- ワープは時間短縮と正の燃料費を持つ。利用可能段階と最大速度は船モデルの上限内。
- より速い段階は時間が短く費用が高い設定だけを受理。
- 見積りは課金しない。確定時に航路開通・距離・出発地・船・段階・資金を再確認。
- 資金不足、期限の整数上限、DB書き込み失敗では残高・航行・履歴を一括して巻き戻す。
- 同じrequest_idの再送は同じ結果を返し、燃料費や航行記録を二重に加算しない。

## 暫定値の隔離と旧データ互換

正式なグレード体系、航行時間換算、ワープ燃料費の式は未確定。
カタログformat 2に任意のnavigation={status,plans}を追加し、船×航路の全組合せを明示する。
plansの行: ship_id, route_id, normal_seconds, warp_options。
warp_optionsの行: level, speed, seconds, fuel_cost。段階ID・速度は同じ船/航路内で重複不可。
statusはprovisionalまたはconfirmed。配布する試遊設定はprovisionalのみ。
速度はモデル内の相対値であり、実際の物理単位や燃料費式を正式仕様にしたものではない。
設定済み通常航行は通常船・仮装巡洋艦でグレードに依存せず同時間、工作船は長い時間となることを検証。

navigation未設定の旧カタログは変更せず保存し、通常航行時間だけ従来speedによる計算を継続する。
これは旧データ互換の動作であり、新船種の正式速度モデルの決定ではない。
旧DBへワープ料金を推測して投入しない。設定がない場合はWARP_NOT_CONFIGUREDで拒否。
新たな設定を既存DBに--configで上書きすることも従来どおり拒否する。
正式な設定導入は企画確認後、別途明示的なカタログ移行として行う。

例: examples/phase3b-trial.jsonは3船種・2グレードの試遊専用。
通常船の通常4秒・fast 2秒/20 Cr・faster 1秒/60 Crなどは正式仕様ではない。
工作船の通常8秒・fast 4秒/12 Cr等も試験値。通常世界とは別DBで使う。
旧版のspeedで料金を課す既存テスト1件は、確定済みの通常航行無料要件に合わせて更新。
それ以外の回帰機能と、過去の要求IDに対応する保存済み応答は維持。

## APIとCLI

Application.quote_navigation(player_id,destination_id,mode='normal',level=None)
Application.navigate(player_id,destination_id,mode='normal',level=None,quote_id=None,request_id=...)
Application.depart(player_id,destination_id,request_id=...)は旧引数・旧応答形式を保つ通常航行。
Application.dock(player_id,request_id=...) / latest_voyage(player_id)。

CLI:
- quote forge normal: 通常時間・0 Crの見積り。
- quote forge warp fast: ワープ時間・燃料費と見積IDを表示。
- warp forge fast: 同じCLIセッションで直前に確認した見積IDを使用して確定。
- warp forge fast 見積ID: 単発CLIや再接続から明示的に同じ見積を使用。
- request trip001 warp forge fast 見積ID: 応答喪失時の安全な再送。
- go forge: 従来コマンド。新規通常航行は無料。
- dock: 現在地で無料係留。voyage: 直近の航行記録と支払額。

見積IDはカタログ・クール・プレイヤー・出発地・船・目的地・段階・費用等への照合用ハッシュ。
認証トークンではない。条件が同じ間は同じIDで、有効期限はまだ設けていない。
再送時はrequest_idだけでなく操作・引数・見積IDを同じにする。
見積後に残高が変わっても料金は変わらず、確定時に支払可能かを再確認する。

## 永続化と移行

schema 4: navigation_policy（カタログの航行設定写し）とvoyages（航行記録）を追加。
schema 1/2/3からバックアップ後に単一トランザクションで移行。
既存テーブル、保存カタログ、言語、BBS識別、資産、貨物、航行期限、要求履歴を保持。
進行中の旧航行はmode=legacy、過去の出発時刻・費用が不明ならnullとして記録。
再計算・返金・再課金しない。旧い要求の再送は旧応答をそのまま返す。
新しい出発は残高・航行期限・操作履歴・航行記録を同一トランザクションで保存。
到着は従来どおり遅延更新、到着時に追加の燃料費や係留費は発生しない。
旧版へ戻す際は旧版と元DB/バックアップを組にする。schema 4は旧版では使わない。

## 確認事項

1. 通常速度・ワープ速度の単位、段階数、最大速度、時間換算と端数処理。
2. 燃料費の計算式。距離・船種・グレード・積荷等のどれを反映するか、最低料金と上限。
3. 工作船の通常/ワープ低速率、同じ段階名を各船で共有するか。
4. スパロウへの正式な船種/グレード対応と、既存カタログへのワープ設定導入方法。
5. 見積有効期限、将来の相場変動下での価格固定期間。現段階は固定設定で照合。
6. 途中キャンセル・返金・航行イベントとの統合。現在は途中キャンセルなし。

無料係留・通常追加料金0 Crは確認待ちに戻さない。
今回の設定表は計算式が未決でも安全に試せる暫定手段であり、最終的な価格モデルに固定しない。
