# v0.19.0 本番Liner notesへの適用手順

これは適用手順であり、本番作業の実施記録ではありません。本番適用は別途承認後に行います。今回の検証はFreeBSD 15.1 / Python 3.12.15の隔離Liner notesで実施しました。実際の本番ディレクトリ・起動管理方法は未確認のため、以下のパスは例です。

## 1. 適用前の確認と保全

- 現行Doorラッパー、doors.conf、Liner notes実行ファイル、起動設定、ゲームDB、マスター/ノード設定、参照鍵、TLS証明書と秘密鍵、サイトプロファイル、利用者別の未確定要求ジャーナルの保存先を確認します。秘密情報を画面やGitへ出しません。
- ゲームDoorへの新規入場を一時停止し、既存のゲームセッションを終了します。未応答操作は既存の結果照会で確定状態を確認し、ジャーナルを消したり別Request IDで再送したりしません。
- 更新処理を停止した状態で、DB・付属WAL等の整合性を確保したバックアップを作ります。SQLite backup APIまたは既存管理CLIを使い、稼働中のDBファイルだけを単純コピーしないでください。認証設定・ソース・BBS設定も非公開領域へ保管します。
- 旧版は削除せず、新版は独立したリリースディレクトリへ置きます。既存DBと設定をソースディレクトリへ移動する必要はありません。

## 2. Liner notesの端末サイズ対応

既存のネイティブPTY Doorと、Telnet NAWS変更をPTYへ伝える処理が必要です。Phase 5の差分は `verification/phase5/freebsd-starroute-resize.patch` にあります。対象は src/doors.h、src/doors.c、src/runtime.c です。

本番の現行ソースに既に同等処理があるか確認します。未導入なら、現行ソースの隔離コピーで差分をレビュー・ビルド・回帰試験し、別途承認した保守時間にLiner notes実行ファイルを切り替えます。バージョン固有のパッチやprepare_resize_copy.pyを本番へ直接実行しないでください。今回のv0.19.0で追加のLiner notes Cソース変更はありません。

## 3. ゲーム本体とDoorの配置

**Inter-BBS:** 新UIはui_infoと価格再検証機能を使うため、マスターを先にv0.19.0へ更新します。既存master設定・DB・鍵・証明書を参照して再起動し、その後BBS側のstarroute_bbsを更新します。参加BBSには薄いクライアントのみ配置し、完全なEngine・秘密宇宙・マスターDBを配布しません。

**スタンドアロン:** 同じホスト上のEngineとDoorをv0.19.0へ揃え、既存ローカルDBと設定を参照します。

両方式とも、新規サイト登録・init・鍵再発行・宇宙生成・クール切替は不要です。設定例を既存設定へ丸ごと上書きしないでください。DBスキーマは11のままで、今回のスキーマ移行はありません。

固定ラッパーの例（実際の配置先へ置換）:

```python
#!/usr/local/bin/python3.12
import sys
sys.path.insert(0, '/private/starroute/releases/v0.19.0')
from starroute_bbs.door import main
sys.argv = ['door', '--config', '/private/starroute/node.json']
raise SystemExit(main())
```

管理者が所有するラッパーに実行権限を付け、既存Door登録から参照します。既存のDoor番号・利用権限・時間制限を保持してください。未登録の場合の形式例:

```text
1|0|3600|/private/starroute/starroute-door|/private/starroute|StarRoute Traders
```

ユーザー識別はLiner notesから渡されるLINER_USER_ID / LINER_USERを利用します。ラッパーに固定ユーザーIDや認証情報を埋め込まないでください。秘密設定は実行アカウントのみが読める権限にします。

## 4. 切替後の確認

1. 80×24のTelnet端末でログインし、既存Door番号から起動。
2. 左星図・右メニュー、2の市場、日英切替、名前切替を確認。
3. NAWSで100列・70列・50列へ変更し、再描画を確認。
4. 購入確認画面で空Enter・N・戻るを試し、資産が変化しないことを確認。
5. 売買・航行等の実取引は事前合意したテストアカウント/少額に限定。航行中のETA・ニュース・WHOと更新操作の拒否を確認。
6. QとCtrl-]でBBSへ戻り、再入場して同じプレイヤー状態を確認。BBSの通常機能も確認。
7. ログ、DB integrity_check / foreign_key_check、未確定要求を確認して新規入場を再開。

隔離試験用 `scripts/bbs_ui_telnet_demo.py` を本番ディレクトリへ向けて実行しないでください。同スクリプトは新規会員・DB・テストTLSを作るためのものです。

## 5. ロールバック

新規入場・更新を止め、未確定操作の結果を確認したうえで、マスターとDoorの参照先を保管したv0.18.0へ戻します。Liner notes本体も変更した場合は対応する旧実行ファイル・設定へ戻します。DBスキーマを戻す作業は不要です。

切替後に確定した取引を消さないため、古いDBバックアップへ無条件に戻してはいけません。DB復元が必要な障害では、確定済み操作・ジャーナル・バックアップ時点の整合性を確認してから個別に復旧します。

詳細な実測根拠は `verification/bbs-ui-v0.19.0/`、操作説明は `BBS_UI_COMPLETE.md` を参照してください。
