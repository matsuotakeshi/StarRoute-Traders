# v0.21.0 — 2026-11-09追加開発統合

交易・市場買取枠、連結航路網と初期停泊先、座標航行・探索・情報ギルド・命名、星図・航行・交易履歴UIを統合する。
原本は独立コピーとして保全し、`INTEGRATION_SOURCES_20261109.json` に統合元ファイルのハッシュを記録した。
既存スキーマ11を維持。新探索ルールの宇宙は旧版へ戻せないので、DBと対応pkgをセットで保全する。
新版クライアントは新版マスターと組み合わせる。旧マスターとの新操作互換は保証しない。

## 新規宇宙

`examples/release-world.json` は探索・市場買取・2時間周期イベントの運用候補に、従来の長時間航行テーブルを組み合わせた暫定テンプレート。
通常船の単位時間720秒、最小時間距離10、工作船・ワープの既存差を維持する。ゲームの標準クールは追加指示に沿い365日。
`scripts/starroute-new-universe.sh` はこのテンプレートの航行時間を60分の1、クールを30日に明示変更する本番管理者用ツール。
通常48惑星と秘密の探索対象を持つ新宇宙・第1クール・プレイヤー0人を作成する。既存DB・設定・鍵をバックアップして保持する。

1. v0.21.0の本体とclientをpkgでインストール/更新する。standaloneではmasterパッケージは不要。
2. ゲーム利用者を退出させ、定期更新・保守・バックアップを停止する。
3. rootで `/bin/sh starroute-new-universe.sh --writers-stopped` を実行する。
4. 全検証後にだけdoor.jsonの参照先が切り替わる。成功時もDoorは停止したまま。
5. 表示された新DBを `starroute-maintain --db NEW_PATH/game.db check` で確認し、定期処理の対象を更新する。
6. `chmod 0755 /usr/local/libexec/liner-notes/starroute-door` で再開し、Telnetで初期状態・売買・航行・復帰を確認する。

スクリプトはpkg 0.21.0 / FreeBSD root / standaloneを要求する。任意の外部writerまで自動検出はできないため、停止済みであることを管理者が保証する。
同期的な検証・生成・バックアップ・置換失敗では旧設定を維持して停止する。電源断/SIGKILLが最後の原子的置換と重なった場合は、新旧どちらの設定かSHA-256で確認してから再開する。
非公開バックアップ内のprepared.jsonは準備記録であり、切替完了記録ではない。旧設定はdoor.json.before、旧DBの整合性確認済みコピーはgame.before.db。
state-and-config.tarはstate/とconfig/という名前で収録する。`/`へ直接展開しない。旧宇宙へ戻す場合は停止中に設定参照を戻し、新旧DBの取引を混在させない。
ログ・宇宙パッケージ・鍵・設定・バックアップをWebやGitへ公開しない。

## 配布と検証

CIは既存全テスト、新規統合テスト、CLI交易/探索デモ、ネイティブ3OSのUI統合/探索Telnetを必須とする。
PRの両必須チェック成功後にmainへ統合し、同一mainコミットのCI成功をリリース前提にする。
本番データには触れず、独立したFreeBSDビルド/インストール環境でpkg新規導入・更新・削除と新宇宙作成を検証する。
実測件数・CI URL・pkg/ZIPのハッシュ・インストール手順は配布物の検証報告に添付する。未検証項目は成功扱いにしない。
