# Phase 3統合版 v0.16.0

2026-11-02。基本指示書、追補No.1〜8、Phase 3完全実装指示書に基づく統合版。
検証の最終件数・結果は配布先のREPORT.txtと実行ログに記載する。

## 実装範囲

- 外部生成器で48惑星・30暫定商品・240×120座標・産業Lvを生成。基本検証/交換パッケージは既存機構を拡張。
- 独立したローカル取り込みコマンドで、新規DBに限りゲームを開始。既存DBの上書きは拒否。
- 開発条件付き船販売。3船種×2グレード、初回通常船はグレード2、破産時は通常船グレード1。
- 航路寄付、工作船効果、共有開通、一回限りのジャックポット、操作履歴と再送防止。
- 保険、保険付き/なしの難破救済、任意破産、再出発。
- 惑星海賊襲来・サイクロン・工場事故、船への海賊襲撃・討伐・磁気嵐・故障・難破、工作船の鉱物発見。
- 確定イベントに関連付けた日英ニュース。市場急騰/急落、航路開通、生産/市場能力の変更も記録。
- 240×120 ASCII星図、端末サイズに応じた部分表示、船中心の追従、英語名トグル、緑の船/停泊惑星、ETA。
- 航行中の状態表示とニュース閲覧、更新操作の拒否。到着はEngineが確定する。
- MasterServiceに船購入/寄付/保険/破産/航行フレーム/ニュースの内部窓口を追加。通信や認証ではない。

旧世界はphase3設定を持たず、追加イベントや販売等を自動適用しない。旧units開発方式をLvへ変換しない。
新サンプルはexamples/phase3-trial.json、生成範囲はexamples/phase3-generator.json、Lv生成はexamples/industry-levels-trial.json。

## 開始手順（管理者専用ローカル環境）

Python 3.10以上、標準ライブラリのみ。Windowsで検証したPythonの版はREPORT.txtに記録する。FreeBSDも同じPythonコマンド構造。
公開Web領域を避け、管理者専用ディレクトリで実行する。FreeBSDではumask 077を設定する。

```text
python -m srt_universe_generator --template examples/phase3-trial.json --parameters examples/phase3-generator.json --levels examples/industry-levels-trial.json --seed YOUR-PRIVATE-SEED --output private-universe.json
python -m starroute.package_check --input private-universe.json
python -m starroute.import_local --package private-universe.json --db new-game.db
python -m starroute --db new-game.db --player pilot --lang ja
```

生成器と取り込みは別プログラム。Engineは生成/GitHub処理を呼ばない。
import_localは検証後に新規DBを排他的に作成する。宇宙レジストリー、既存世界切り替え、本番Deploymentではない。
SHA-256は完全性チェックであり、配布元の真正性/署名を保証しない。秘密パッケージをBBSへ送らない。

## CLI

既存register/status/market/buy/sell/go/quote/warp/development/invest/production等を維持。

| コマンド | 用途 |
|---|---|
| map [幅 高さ] | 星図。引数なしでは端末寸法から範囲を決定 |
| map-names on/off | 正式英語名の表示切り替え。航行中は変更禁止 |
| news | 最新100件の閲覧可能な確定ニュース |
| shipyard | 現在地の販売船、価格、容量、購入可否 |
| ship-buy 船ID | 旧船との交換購入 |
| donate 航路ID Cr | 現在地に接する未開通航路へ寄付 |
| insure | 現在の船の保険に加入 |
| bankrupt | 暫定清算方式で再出発。実行により貨物/現金等を変更 |
| request 要求ID 操作 引数 | 上記の更新操作にも再送防止を適用 |

航行中のstatus/mapは表示フレームの再表示であり、追加のゲーム行動ではない。news以外のゲーム行動、船購入/保険/破産を含む更新は禁止。
go/warp/statusで星図とETAを表示し、wait中は毎秒再描画。端末入力待ち中の自動再描画は行わない。BBS用常時画面更新はPhase 5のUIで扱う。
ETAの時刻はEngineの整数時刻（現在の実時間方式ではUnix秒）と残秒を表示。
停泊時は緑の*を維持し、空きがあれば隣接セルに緑の+を描く。極小領域で空きがない場合は船記号優先。
描画の240×120座標と内部座標は分離。旧小規模宇宙を表示しても航路距離や航行費を変えない。
このCLIは信頼されたローカル用。参加BBSは将来MasterServiceの公開窓口から得たデータのみを使う。

## 暫定パラメータと方式

全て正式バランスではない。数値はサンプル設定から変更可能。方式名が異なる未知設定は黙って解釈せず拒否する。

| 項目 | 統合サンプルの値/方式 |
|---|---|
| 初回資金/船 | 5,000 Cr / normal_2、容量40 |
| 再出発 | 1,000 Cr / normal_1、容量20。初回開始地点へ移動、貨物清算、保険解除。既存台帳/共有開発/アカウントは保持 |
| 通常船価格/保険 | G1:1,000/100 Cr、G2:2,000/200 Cr |
| 仮装巡洋艦価格/保険 | G1:1,500/50 Cr、G2:3,000/100 Cr |
| 工作船価格/保険 | G1:1,500/100 Cr、G2:3,000/200 Cr |
| 販売条件 | G1条件なし、G2は第2次産業Lv1以上 |
| 交換 | 下取り返金なし、貨物維持、積載超過なら全体拒否。購入時に旧保険解除 |
| 通常航行/係留 | 常に0 Cr。ワープは既存の船別・段階別時間/Cr表を使用し、燃料商品と独立 |
| 船の航続距離 | 新240×120サンプルは120、旧世界の距離は維持 |
| 投資 | 1Lv当たり第1次100、第2/3次150、第4次200 Cr。工作船25%追加効果、端数をプレイヤー/惑星/産業別に保存 |
| 上限 | 上限超過投資は全額拒否・無課金。最大Lvは生成設定1〜5、初期0〜最大。全体上限5は正式決定ではない |
| 生産/市場 | 生産は基礎量＋基礎量×Lv×50%、市場容量は基礎容量＋基礎容量×第3次Lv×10%、整数切り捨て |
| Lv0 | 基礎生産/基礎市場容量を保持 |
| 災害 | 現在Lvを1低下、最低0、最大Lv維持。再投資で復興 |
| 被害産業 | 海賊襲来:第2/3/4次、サイクロン:第1/3次、工場事故:第2次 |
| 効果の時刻 | 既に始まった生産期間を旧能力で完了し、次の期間から新能力。容量低下時に超過在庫は境界で切り捨てる暫定方式 |
| 航路 | 開通効果閾値は距離×10、工作船25%追加、端数を航路別に保存。余剰寄付も受理 |
| ジャックポット | 最後の寄付者へ実支払累計の10%、一度のみ。支払額と効果量を別記録 |
| 保険 | 一回の難破で消費。貨物消失、船保持、購入価格の25%を現金補償。未加入は低グレード船と再出発資金で救済 |
| イベント周期 | 300秒。海賊/討伐各1%、磁気嵐/故障各0.5%、難破0.05%。惑星災害各種0.1%/惑星/周期 |
| 船の被害/報酬 | 海賊は現金10%損失、磁気嵐30秒遅延、故障は最大50 Cr。討伐戦利品2単位、積載可能量まで |
| 鉱物発見 | 基本0.5%＋第1次Lv×0.2%＋資源豊富度合計/100 basis points、上限100%。希少抽選5%。Lv0でも可能 |
| 係留対策 | 経過周期で抽選し、係留コマンド回数では抽選しない。船購入/到着/再出発で資格開始時刻を管理 |
| 相場ショック | 300秒ごと、各対象急騰1%/急落1%、+300/-200 Cr、120秒。既存の価格上下限と需給補正を維持 |
| 更新上限 | 新イベントは一回1,000周期まで。超過時は同期要求を返し、既存events-syncで段階処理する |

30商品は既存5IDを維持し、25品を追加した暫定サンプル。以前提案された28品の完全な一覧は今回参照した資料では確認できず、同一の一覧を復元したとは扱わない。品目名/価格/生産は設定・日英辞書で調整可能。
有料ギルド通信、WHO、探索そのものの進捗管理は今回追加していない。破産で未実装の探索データを削除する処理もない。

## 永続化と互換性

DBスキーマ9→10。既存移行手順にバックアップとphase3_stateテーブル作成を追加。1〜8からの移行も維持。
phase3_stateはクール単位のJSON状態を持ち、保険、出発/区間時刻、投資端数、航路支払/効果/報酬、確定イベント、ニュースを保存する。
現在位置は保存済みの出発時刻/座標/到着時刻からEngineで再計算。磁気嵐時は区間開始位置を保存し、位置が逆戻りしない。
既存player_state/markets/routes/planet_developmentと同じトランザクションで更新。更新要求IDと結果も原子的に保存し、再送は確定済み結果を返す。
難破保険と任意破産は別処理。破産直前のグレードを再出発基準にしない。
産業被害で期間中の能力が現在Lvの能力を一時的に上回っても保存再開できるよう、能力の保存値は非公開最大値の範囲内で検証する。
共有ルール版phase3-complete-1、設定スキーマ10。新パラメータはハッシュ対象、現在Lv/被害/ニュース等は対象外。
旧世界のルール値は維持するが、照合用版/ハッシュは更新。過去台帳の記録済みハッシュは書き換えない。

## 検証と制約

```text
python -m unittest discover -s tests -v
python scripts/phase3_demo.py --directory PRIVATE-EMPTY-DEMO-DIRECTORY --lang ja
python scripts/phase3_demo.py --directory ANOTHER-EMPTY-DEMO-DIRECTORY --lang en
```

デモは外部プロセス生成→新規取り込み→CLIの交易/星図/航行/ニュース/投資/寄付/船購入/保険→固定災害注入→保存再開を行う。
固定時計と内部のテスト用イベント呼出しを使用する。本番確率をテストのために変更せず、プレイヤー用注入コマンドは公開しない。
難破/特殊船/破産、競合最終寄付、原子的拒否、時間更新の再現性、公開窓口の秘密情報除外も自動テストする。
最新100件のみをCLIに表示するが確定履歴は保持する。現段階は小規模世界の一括読込/保存であり、本番長期運用の履歴分割/性能はPhase 4/5で評価する。
SHA-256と公開情報分離は認証の代わりではない。現行ローカル用操作窓口を無認証で外部公開してはいけない。
