# 追加指示書No.6：集中型マスター方式とPhase 3基盤

2026-11-01 / v0.14.0。ユーザー提示の追加指示書No.6を優先する。
集中型マスター方式は確定仕様。**共有世界の生成・保存・判定・更新はマスターだけが行う。**
BBSは表示・入力・ユーザー識別・API要求・許可された情報のキャッシュを担当する。

## 既存実装との照合

| 項目 | 照合結果・今回の対応 |
|---|---|
| EngineとUIの分離 | 既存Engine / Application / CLIを維持 |
| 固定宇宙と動的状態 | 生成カタログと市場/開発/イベント等のDB状態を維持 |
| 一度だけの生成 | 管理者が新規世界向けに生成・凍結。既存DBへの異設定を拒否。マスター専用と明記 |
| 名前空間 | 既存bbs_accountsによるBBS_ID / USER_ID別プレイヤーを維持 |
| 共有ルール | 設定一元化と正規化SHA-256を維持。今回ゲームルール値は変更しない |
| 原子的な更新 | 既存SQLiteトランザクション・所持金/在庫/貨物の検証・台帳を維持 |
| 再試行 | 既存操作履歴を使い、更新要求のIDを新窓口で必須化 |
| 公開/秘密の境界 | 公開許可の明示と項目の許可リストを新規追加 |
| 宇宙・クールの対象確認 | 更新と同じトランザクション内で照合するガードを追加 |
| 将来API用操作窓口 | ネットワークを持たないMasterServiceを新規追加 |
| 結果不明時の照会 | 操作履歴を照会する、時間を進めない内部機能を追加 |
| 通信・認証・接続判定 | Phase 5のまま。未実装 |

## Phase 3で追加した窓口

`starroute/master.py` はマスター内でのみ使う操作インターフェース。
HTTPサーバー、エンドポイント、TLS、サイト認証、接続許可判定、BBS用クライアントは実装しない。
操作名・引数・内部の結果形式は基盤用の契約であり、正式な通信プロトコルではない。

`ServerContext` はマスターの信頼されたコードだけが構築する。
対象Universe ID / Round ID、BBS ID、BBS内User ID、公開許可を含む。
**BBSから届いた本文をそのままServerContextに変換してはいけない。**
Phase 5で認証されたサイトIDと照合し、プレイヤーの公開許可をマスター上の記録から取得する。
このクラスを持っているだけでは認証済みであることを証明できない。今回認証機構を実装したとは扱わない。

対応操作は登録、自分の状態、市場、生産、開発、許可された航路、売買見積、売買、投資、航行見積、航行、係留。
価格・合計額・資金・プレイヤーID・BBS ID・宇宙ID・公開許可などを操作本文に追加した要求は拒否する。
価格・数量・所持金・積載量・投資・航行費用は既存Engineで判定する。
内部機能への任意メソッド呼び出し、宇宙生成、全イベント履歴、全設定取得はこの窓口から許可しない。

航行はマスター内の同一トランザクションで見積を再計算して実行する。
完全なカタログから作る既存ローカルCLIのquote_idはBBS向け応答には含めない。
通信APIでの見積の有効期限・価格確認・トークン方式はPhase 5の詳細設計事項とする。

## 公開情報の切り出し

`Visibility` では惑星ID・座標公開ID・航路IDを別々に指定する。既定値は空集合。
公開許可はサーバーからのみ供給し、具体的な探索/発見ルールや永続的な探索記録はここで創作しない。
航路は明示的に許可され、両端惑星も公開されたものだけ返す。
「閉鎖」と「未発見」は別概念。閉鎖航路でも、マスターが発見済みと認めて明示的に許可すれば表示できる。

公開定義は許可された惑星ID/表示名/座標、許可された航路ID/両端/距離だけ。
資源詳細・非公開上限・シード・元テンプレート・産出定義全体・非公開イベント情報を返さない。
動的な市場、生産、開発は現在地が許可範囲内であり、既存Engineの閲覧条件も満たす場合だけ返す。
開発情報から資源項目は除外し、許可された現在の進捗だけを公開する。
自分の資金・船・貨物・所在地などは本人用の状態情報として返す。
将来内部返却値に秘密項目が増えても、自動的に公開されないよう応答を許可リストで構成する。

旧CLIとApplicationはマスター内の信頼された操作用として維持する。
従来CLIは閉鎖航路やローカル設定情報なども扱うため、BBS向けAPIとしてそのまま公開しない。
`universe.public_info` と `Application.configuration_info` は従来名を互換のため残すが、BBS公開窓口ではない。
マスターのDB、生成JSON、設定、シード、完全なカタログをBBSへ配布してはならない。
配布アーカイブはマスター管理者向けソースであり、BBSクライアント配布物ではない。

## ハッシュ・識別・冪等性

ゲームルールのハッシュと、マスター専用の完全宇宙定義ハッシュは既存のまま維持する。
新たな `public_definition_hash` は対象Universe/ Round、公開投影版1、許可された固定情報のみから生成する。
現在価格・在庫・開発進捗・航路の現在の開通状態は公開固定定義ハッシュに含めない。
同じ公開範囲なら異なるBBSのプレイヤーでも同じ公開ハッシュになる。
閲覧範囲が違うプレイヤーではハッシュも変わるため、その差を設定異常と判定してはいけない。
言語表示はBBS側で扱い、ゲームルールの照合へ含めない。
公開ハッシュは真正性を証明する署名ではない。

生成世界は保存済みUniverse IDを使用。旧形式の世界は既存world_idを宇宙識別子として用いる。
Round IDは現在のseason_idに対応する。新たなDB移行は不要で、スキーマ9を維持する。
対象の照合はトランザクション内で、操作履歴の再送結果を返す前・ゲーム時間の更新前に行う。
旧宇宙/旧クールを指定した要求を、新しい対象へ転用しない。
Phase 4のクール切替・複数宇宙履歴のデータ設計自体は未実装。

登録・売買・投資・航行・係留では操作IDを必須とする。
登録はBBS/ユーザー、他の操作は紐付いたプレイヤーとクールで既存の操作履歴を検索する。
同じIDで異なる内容を送ると拒否し、同じ内容なら確定済み結果を返す。
対象照合・検証・資金/在庫/貨物変更・台帳/結果保存は同じトランザクションで行う。

`result` は対象操作とIDを指定し、確定済み結果を照会する。別BBSの同じUser IDの結果は返さない。
確定履歴があればcommitted、見つからなければunknownとする。unknownを失敗確定と解釈しない。
結果照会ではゲーム時間・生産・イベントを進めず、操作を再実行しない。
登録とその他の操作のキー空間、保存期間、HTTP要求でのキー形式等はPhase 5で正式に設計する。

## Phase 4への引き継ぎ

- 前クールのランキング/殿堂を保存し、新しいUniverse IDとRound IDへ切り替える。
- マスターだけが新宇宙を生成し、共有状態を初期化する。
- 切替中の更新停止、対象ID照合、旧クールの更新禁止を組み合わせる。
- 古い操作履歴と結果照会の保持範囲を定める。旧要求を新クールに適用しない。

## Phase 5への引き継ぎ

- 認証/暗号化API、サイト登録/削除、認証済みBBS IDと要求の照合。
- マスターが管理する正規設定を、信頼できる方法で検証する。
- 自サイト/接続先の正常、異常、双方異常、検証不能を分類。無応答を設定異常と断定しない。
- 設定/プロトコル/宇宙/クール不一致や真正性の検証不能時は更新を許可しない。自動上書きしない。
- 公開投影に対する署名・版管理、本人ごとの閲覧制御、共有状態の更新・同時アクセス制御。
- 通信断時はBBSで新規更新を停止。ローカルEngineへの切替や、復旧後にローカル結果を同期する方式は禁止。
- 必要なら許可済み情報だけを読み取り専用キャッシュで表示し、古い情報である旨を日英表示する。
- キャッシュは少なくとも宇宙/クール/サイト/利用者/公開範囲を混同しない設計とし、詳細方式は未確定。
- 復旧時に再認証・整合性再確認を行い、応答喪失した操作の確定結果を照会する。
- 監査ログ、不一致分類、接続障害との区別、設定版/ハッシュ/不一致項目、バックアップ/復旧/監視。
- APIのパス、認証方式、署名方式、タイムアウト/再試行、キー仕様、同時人数、オンライン表示、冗長化は未決定。

## 検証範囲

マスター内で複数のBBSを表すコンテキストとSQLite接続を用い、最後の在庫の競合、同じ資金の競合、
積載制限、投資再送、トランザクション失敗、確定結果の再照会、旧宇宙/クール拒否、公開範囲を検証する。
これは通信API、認証、ネットワーク断、正規設定の接続拒否の成功試験ではない。
それらの必須テストはPhase 5へ割り当てる。ジャックポット重複支給の試験は当該機能の実装時に追加する。

実行：`python -m unittest discover -s tests -v`。
日英のマスター内デモ：`python scripts/master_demo.py`。
既存CLIの交易/航行/産業/宇宙生成のデモも引き続き使用する。
