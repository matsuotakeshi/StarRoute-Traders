# ECON-04 v0.11.0：相場イベントの再現・保存と価格統合

## 試遊方式

market_events.mode=slot_shocks_v1 / status=provisional。seed、interval_seconds、duration_seconds、targetsを設定します。各targetはplanet_id/goods_id、surge_bps/crash_bps、surge_credits/crash_creditsを持ちます。確率は0〜10,000の整数で合計10,000以下、補正額は正の整数Cr。継続期間は抽選間隔以下。
例のevents-trial.jsonは60秒ごと、継続30秒、急騰/急落各1,500 bps、+200/−150 Cr。商品/惑星ごとに変更可能です。正式なバランス値ではありません。

各市場・各区間で最大1件。重複、延長、積み重ねは行いません。区間末で終了し、次の抽選区間には独立に参加します。この重複方針も試遊方式の一部で、正式確定ではありません。

## 再現性と保存

SHA-256へ方式版/seed/クールID/区間番号/惑星ID/商品IDの固定JSONを渡し、整数を10,000で剰余化して抽選します。Pythonの乱数状態や実行順序に依存しません。これは試遊の決定的抽選で、秘密性や予測困難性を保証しません。公開seedによる予測を許すか、運用seedの管理と配布は正式運用前の確認事項です。
DBスキーマ8: event_clockにクールの起点と処理済み区間、market_event_historyに発生区間・対象・種類・補正・開始/終了時刻を保存。履歴は削除せず、終了は保存されたends_atとゲーム時間から判定します。別の終了抽選/終了時の価格上書きはありません。
1〜7からバックアップ後に原子的移行。旧世界はイベント無効、過去へ遡って抽選しません。旧ゲームデータ・世界ID・台帳・要求結果を維持します。

抽選・時計・経済更新・取引を同じトランザクションで保存。再送は元結果を返し、新しい時間の抽選を強制しません。同時アクセスでも各区間を一度だけ処理。失敗時は履歴と時計もロールバックします。

一度に処理する未消化区間は最大1,000。超過すると通常操作をEVENT_SYNC_REQUIREDで拒否し、events-syncで1,000区間ずつ保存します。pending=Falseになるまで繰り返してください。履歴を捨てず、通常操作が未同期の価格で進まない設計です。全市場対象なので処理量は対象市場数にも依存し、無制限の大規模負荷を検証したものではありません。

## 価格統合

地域基準（地域方式無効時は従来基準）+有効イベントのCr補正を、既存の在庫補正と数量別単価計算へ渡し、既存min_price/max_priceで制限します。倍率ではなく加算式が今回の試遊方式です。
終了時には現在の需給で価格を再計算し、発生前の在庫/価格へ巻き戻しません。生産・需要・貨物・投資は独立して進みます。燃料商品も同じ経済ルールですが、ワープ費・貨物消費には連動しません。

## CLIと公開範囲

- events: 現在地で有効なイベント。係留中のみ。
- events-history [after_sequence]: 世界全体の履歴（既定50件、内部API上限100件）。ログIDで継続取得。
- events-sync: 長期間の未処理区間を分割同期。

対象・種類・補正額・開始/終了時刻は試遊では公開します。seed、非公開開発上限、資源特性値を応答へ含めません。世界全体のイベント公開範囲・補正値の公開方針は確認事項です。
旧方式はmarket_events未指定/null/disabledで無効。新規DBへexamples/events-trial.jsonを指定します。scripts/events_demo.pyは独立一時DB・手動時計・発生率100%の試験条件で、急騰/急落・売買・再開・終了をCLI確認します。稼働データの時間を変更しません。

## 設定ハッシュと未決事項

方式・seed・期間・市場別確率/補正はGame Rulesへ登録。rules_version=phase3-events-1、設定射影6、DB8。動的な処理済み区間/履歴/有効イベント/在庫/進捗は設定ハッシュに含めません。ターゲット集合順・言語変更に不変で、別環境の抽選も再現可能です。
正式な確率/規模/期間、倍率か加算か、同時イベント/延長/終了方式、公開情報、seedの運用/予測対策は確認事項です。今回は明示した試遊方式だけ実装します。ECON-05の開発効果とInter-BBS通信/接続判定（Phase 5）は追加していません。
旧DBへ新設定を自動適用しません。旧版へ戻すには移行前バックアップを使用。外部言語ファイルは新しいevents関連表示/エラーキーを追加してください。
