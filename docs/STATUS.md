# 実装・検証報告

2026-11-01 / StarRoute Traders 0.1.0

## 完了

- Phase 1: 参考資料照合、矛盾・不足点、アーキテクチャ、データモデル、時間処理、
  共通API、将来Door/Web境界、クール制、テスト方針をDESIGN.mdへ記録。
- Phase 2: プレイヤー登録、惑星、商品、市場、売買、船、積載量、現金、
  航路移動、出発/到着、DB永続化、対話CLI、単発CLI、UIなしデモ。
- ローカル複数セッションの共有在庫。競合操作はDBトランザクションで直列化。
- ゲーム定義JSONとDBへのスナップショット保存。設定不一致・未知スキーマを拒否。

## 暫定仕様

Python標準ライブラリ＋SQLite。3惑星・3商品・1船・3航路は試遊データ。
資金5,000 CR、船容量20、燃料なし、試遊航路費0、航行2〜4秒。
時計は実時間/遅延更新。市場は価格固定、売買による在庫変化のみ。
商品生産量・価格変動特性は保存するが、動作はPhase 3。
第1クールの状態分離のみ実装し、終了/リセットはPhase 4。

## 未実装

相場変動/回復/急騰、生産補充、航路寄付/開通/報酬、海賊/磁気嵐/故障/難破、
保険/再起救済、ギルド/ランク、探索、利益台帳/ランキング、クール終了/殿堂、
Liner notes認証/起動/結果投稿、Web UI。
これらの成功を返すダミーAPIや検証済みと見せるskipテストは作っていない。

## 検証

Linux / Python 3.12.14。自動テスト40件成功（tests/test_game.py）。

- Engine単独で売買→航行→利益、容量/資金/在庫/保有制約、不正数量、ID・表示名検証。
- 同一市場の往復で資金増加なし。部分売却と容積2の商品も検証。
- 出発可能経路、双方向、閉鎖、航続距離、船速、航行費、航行中の禁止操作。
- 到着時刻の境界、再更新の一回性、時計後退の抑止。
- 整数上限、資金・在庫の桁あふれ拒否。
- SQLite再接続後の積荷/出発状態、複数接続の市場共有。
- 2人が最後の在庫1個を並行購入し、1人だけ成功。
- ルール失敗/途中例外/DB制約失敗で操作全体をロールバック。
- カタログの永続化、設定不一致、未対応DB形式、外部キー。
- CLI Adapterと別プロセスCLIからの売買/移動/保存。

UIなし自動デモ: 5,000 CR → 600 CR購入 → 1,200 CR売却 → 5,600 CR。
対話CLIも実時間のwaitを含む同じ交易手順を別DBで実行して確認。
実機FreeBSD/Windows、長時間負荷、ネットワーク越しの接続は未検証。
Phase 3/4の機能テストは各機能の実装と同時に追加する。
