# Phase 3C v0.7.0：取引台帳・数量別価格・市場需給

## 実装範囲

取引台帳、数量に応じた限界単価の合計、共有市場の供給/需要と時間経過による在庫回復を追加しました。既存世界の経済設定未指定時はfixedで従来の価格と在庫更新を維持。stock_curve_v1は明示的に選ぶ試遊方式です。正式な経済式や数値を確定したものではありません。
ランダム変動・急騰、投資と生産の連動、利益評価/取得原価の方式は未決のため実装していません。Phase 3Cの残タスクとして保持します。

## 設定（共有Game Rules）

例: examples/phase3c-trial.json。元の試遊船/航行設定にeconomyを追加。

- mode: fixed または stock_curve_v1。未指定/nullとfixedは同じ有効設定。
- status: 試遊方式ではprovisionalのみ。説明用でハッシュから除外。
- tick_seconds: 需給更新間隔（正の整数秒）。
- markets: 全惑星/商品を重複なく列挙。
- target_stock: 価格計算の基準在庫。
- step_price: 在庫1個の差による単価変化（正の整数Cr）。
- min_price / max_price: 単価下限/上限。
- stock_limit: 市場の在庫上限。初期在庫/基準在庫以上。
- supply_per_tick / demand_per_tick: 期間ごとの供給/需要数量（0以上）。既存goods.productionは予約値のまま、この方式ではこれらを使用。

試遊例は60秒ごとに供給3・需要1、基準在庫は初期在庫、単価変化1 Cr、価格範囲1〜10,000 Cr、在庫上限10,000。すべて暫定値です。

## 暫定計算方式

初期市場価格をb、基準在庫をT、現在在庫をS、変化幅をkとし、P(s)=clamp(b+k*(T-s),min_price,max_price)。
数量qの購入合計はP(S-q)〜P(S-1)の和、売却合計はP(S)〜P(S+q-1)の和。購入の最初の単価はP(S-1)、売却はP(S)。整数Crのみで丸め誤差なし。上限/下限込みの等差数列を定数時間で合計し、巨大数量の逐次ループを避けます。
同時点なら一括と分割の合計が一致し、買って直ちに同量売っても利益を作れません。複数人の取引は同じ在庫を参照し、DBトランザクションで直列化します。

需給は全期間数nに対し S'=clamp(S+n*(supply-demand),0,stock_limit)。供給・需要は同時に相殺するモデルで、逐次の供給→消費とは異なります。経過期間の端数を保持し、再起動や同時アクセスで二重更新しません。時計後退は既存のgame_time単調増加規則に従います。バックグラウンド処理はなく、ゲーム操作時に遅延更新します。失敗した操作は時間更新もまとめてロールバック。

## 台帳

trade_ledgerにクール・プレイヤー・惑星・商品・売買・数量・総額・最初/最後の単価・在庫前後・現金前後・時刻・request_id・ルールハッシュ・価格方式を保存。世界は既存world_idで識別。資産変更・市場変更・操作履歴・台帳は同一トランザクション。失敗や再送で二重記録しません。
履歴取得はプレイヤー別、sequenceカーソル、既定50件/上限100件。CLIはledger [after_sequence]で継続取得。単体CLIのplayer指定は従来同様に信頼されたローカル利用向けで、外部認証ではありません。
未分類フィールドを含む旧カタログではルールハッシュをnullとして記録し、検証済みと偽りません。新形式の試遊設定ではハッシュを保存します。
過去の操作履歴はそのまま保存し、旧取引の台帳や損益を推定生成しません。旧request_idの再送は旧結果を返し、台帳を新規作成しません。台帳の記録開始はこの版への移行後です。取得原価/FIFO/平均原価等の損益計算は未確定。

## CLI

```sh
python3.12 -m starroute --db data/economy-trial.db --config examples/phase3c-trial.json --player captain
```

```text
register Captain
market
trade-quote buy grain 3
request trade01 buy grain 3
request trade01 buy grain 3
ledger
trade-quote sell grain 3
sell grain 3
config-info
```

marketの単価は次の1個の買値（在庫0では参考値）。trade-quoteは最初/最後の単価と合計を示します。見積りは価格予約ではなく、資金/積載/所有貨物の充足も保証しません。確定売買では最新在庫・価格と全制約を再検証します。必要な価格固定/スリッページ上限機能は企画確認事項です。

## 互換性・ハッシュ

DBスキーマ6。旧1〜5からバックアップ後に原子的移行。economy_clockとtrade_ledgerを追加し、旧テーブルのゲームデータ・世界ID・進行中航行・既存要求結果を維持。移行時のgame_timeを需給時計の起点とし、過去の期間を勝手に適用しません。
既存DBの設定をファイルで上書きする処理は追加していません。試遊方式は新規DBで使用します。旧版に戻す場合は移行前バックアップを使用。
rules_version=phase3c-1、config_schema_version=2。economyの有効設定を共有ルールに含め、marketsは惑星/商品ID順で正規化。サイト設定と可変在庫は除外。バージョン変更により旧版とハッシュは変わりますが、旧見積り用canonicalや保存済み要求の内容は変更しません。
Inter-BBS通信・接続可否判定はPhase 5のまま。

## 確認事項・残タスク

1. 正式な数量別価格式、売買差額、価格上下限と変動幅。
2. 供給/需要/回復式、更新間隔、在庫上限、goods.productionと産業投資の接続。
3. ランダム変動/急騰の発生率・期間・規模、乱数再現性/保存方式。未実装。
4. 取引利益の取得原価評価、ランキングへの計上、移行前履歴の集計方針。
5. 見積り価格の固定時間/有効期限、価格差の許容範囲。

これらを正式値として固定せず、現在の試遊方式を置換/追加できるmodeとして分離しています。
